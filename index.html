Overview

Features

From the moment someone clocks in to the salary slip at the end of the month.

Attendance screen

A large live clock, a searchable employee dropdown, and one clear action: Clock In or Clock Out.

Reliable clocking

Server time only, no duplicate clock-ins or clock-outs, and safe retries after a network failure.

Shifts

Day, overnight, flexible and 24-hour shifts, grace periods, working days, holidays and leave.

Shift assignments

For one person or many at once, with effective dates and full history.

Attendance tracking

Late arrival, early departure, overtime, half day and missing clock-outs, worked out automatically.

Corrections with a trail

Every change records who, when, the old value, the new value and the reason.

Overtime and pay

Employee types, basic salary and OT rates, with overtime hours added by managers.

Salary slips

Monthly salary with allowances, deductions and overtime, and a printable A5 slip.

Reports and Excel

Eleven reports with filters, exported as Excel, CSV, JSON or PDF, or all at once in one workbook.

Company card

Your company profile, shown when anyone clicks the company name on the attendance screen.

Access control

Super Admin, Admin, Manager, Attendance Manager and Viewer, enforced by the server.

Backups and safety

One-click backup and restore, plus Super Admin tools to purge data or reset to defaults.

Supports up to 999 employees, with IDs from EM001 to EM999. IDs are permanent and never reused.

Before you start

Requirements

Computer

Windows 10 or 11 for the one-click launcher. macOS and Linux work with the manual install.

Python

3.10 or newer. On Windows, the launcher installs it if it is missing.

Browser

A current version of Edge, Chrome or Firefox.

Internet

Needed the first time only, to download Python and the required components. After that, Timora runs offline.

Install

Quick start on Windows

  1. Get the code With Git, or on the GitHub page choose Code > Download ZIP, then right-click the file and choose Extract All. 
    git clone https://github.com/JayashankaAnushan19/timora_attendence_shift_clockIOut_mng_system.git
cd timora_attendence_shift_clockIOut_mng_system
  2. Double-click start-timora.bat That is the only step. The first start can take a few minutes, and later starts take a few seconds.
  3. Keep the window open Timora runs while that window is open. Closing it stops Timora.

What the launcher does

  1. Looks for Python 3.10 or newer. If it is missing, it installs Python 3.12 using winget, or from python.org if winget is unavailable.
  2. Creates a private environment in a .venv folder.
  3. Installs the required components. This needs internet the first time.
  4. Creates the database on first run.
  5. Starts Timora and opens it in your browser.

If something goes wrong, the window explains the problem and how to fix it.

Install

Updating to a new version

  1. Close the Timora windowIf it is open.
  2. Get the latest code In the Timora folder, run the command below. If you use a ZIP instead, extract the new ZIP over your existing folder. 
    git pull
  3. Double-click start-timora.batIt installs any new components the update needs.

Your data is kept. The database is upgraded automatically the next time Timora starts. Make a backup under Backup & Restore before updating, just in case.

Updates do not change data you already have. Your existing shifts and settings stay as they are, and the starter employee is only added to a brand-new installation.

A ZIP contains no database or backup files, so yours stay as they are. It does contain config/settings.json, so if you changed the host or port there, change it again afterwards.

Admin panel

First-time setup

Log in to the admin panel, then:

  1. Set your timezoneIn System Settings, set Business Timezone. It starts as UTC, and all clock times and shift rules follow it, so this comes first.
  2. Enter your company detailsSet the company name and logo, then fill in Company Profile. These appear on salary slips and on the company card, which anyone can open from the attendance screen without logging in.
  3. Review the shiftsUnder Shifts, edit the starter shifts below or create your own.
  4. Add holidaysOn the Shifts page, open the Holidays & Non-Working Days tab.
  5. Add employeesUnder Employees, add each person with their type, shift, basic salary and OT pay rate per hour. IDs are generated automatically. To change the types or show a currency, use Employee Settings in System Settings.
  6. Add other administrators, if neededUse User Access Management. Anyone who adds overtime needs their own login with the Manager role or higher.

Install

Use from other computers on the network

By default, only the computer running Timora can reach it. To let other computers connect:

  1. Change the hostOpen config/settings.json in a text editor and set "host" to "0.0.0.0". To restore the default, set it back to "127.0.0.1". 
    {
  "host": "0.0.0.0",
  "port": 5000,
  "database": "database/timora.db",
  "backup_dir": "backups",
  "max_upload_mb": 200
}
  2. Restart TimoraClose the window and double-click start-timora.bat again.
  3. Allow it through Windows FirewallWhen asked, allow it on Private networks only.
  4. Find the server's addressRun ipconfig and note the IPv4 Address.
  5. Open it on the other computersGo to http://<that address>:5000/, for example http://192.168.1.20:5000/.

Traffic is not encrypted on plain HTTP, so use this only on a network you trust.

How it works

Attendance rules

All times are stored in UTC and shown in the business timezone. An overnight shift belongs to the date it starts on. The examples use a 09:00 AM to 06:00 PM shift with a 10-minute grace period.

RuleHow it worksExample
On timeClock-in up to the end of the grace period09:05 AM is on time
LateClock-in after the grace period, measured from the shift start09:15 AM is 15 minutes late
Early arrivalClock-in before the shift start, within the early allowance08:45 AM is 15 minutes early
Early departureClock-out before the shift end04:00 PM is 2 hours early
OvertimeClock-out after the shift end, once past the minimum overtime (default 15 minutes)07:30 PM is 1h 30m overtime
Half dayWorked less than the half-day threshold (default 50%) of scheduled hours
Incomplete attendanceNo clock-out before the late clock-out allowance ends (default 4 hours)An administrator can add the clock-out
  • Clock-in window: opens before the shift by the early allowance (default 60 minutes) and closes at the shift end.
  • Breaks: the shift's break is deducted from worked time when the employee worked at least half of the scheduled shift.
  • Flexible shifts: never flagged late or early, and overtime is based on hours worked.
  • 24-hour shifts: a shift that ends on Day 2 at its start time is a full 24-hour window. Marked flexible, as the Default and Midnight shifts are, it shows Present once the employee clocks out, with no late, early, half-day or overtime flags. On the Default Shift, a clock-in at 03:00 AM counts towards the attendance day that started at 8 AM the day before.
  • One status per record: when several apply, the priority is Half Day, Late, Early Departure, Overtime, then Present. The durations are kept regardless, so reports count them all.
  • Absent: worked out from the schedule when a scheduled shift ends with no attendance.
  • Past records: each record keeps the shift times it was worked under, so editing a shift later never changes history.

Most of these values can be changed per shift or in System Settings.

How it works

Shifts and starter data

Deleting a shift

Super Admins and Admins can delete a shift from the Shifts page. Other roles cannot, even if they can manage shifts.

  • Move everyone off the shift first under Shift Assignments. A shift with employees assigned today or later cannot be deleted.
  • At least one shift must remain.
  • Past attendance records keep the deleted shift's name, and its code can be used again.

To stop using a shift for now without removing it, choose Deactivate instead.

Starter data

A new installation starts with the three starter shifts and one employee, Heyshan Senaviratne (EM001, Manager, on the Manager Shift). He comes from config/starter_data.json. His joining date is set to the installation date, so update it under Employees, along with his basic salary and OT rate.

This data is added only once, to an empty system. To start again from nothing, stop Timora and delete database/timora.db. This erases all data, including settings and admin accounts.

Pay

Overtime and pay

Add overtime: on the Overtime page, choose Add Overtime, enter the date, hours and reason, and choose selected employees or all active employees. To undo an entry, cancel it with a reason. Entries are never deleted.

Who can do what: the permissions are tied to the role on a person's login, not to their employee type. Marking someone as a Manager employee does not give them a login.

Added OT hours×OT rate per hour=OT pay
  • Each entry keeps the rate in force when it was added, so changing a rate later does not change earlier pay. Set the rate before adding overtime.
  • Added overtime is separate from attendance. It does not change clock times, worked hours or status, and it appears as its own line on the salary slip.

Only hours added on the Overtime page count towards pay. Overtime worked out from clock-out times appears in the Overtime Report but is not paid automatically, so nothing is paid twice or without a manager's approval.

Pay

Salary slips

Open Salary in the admin panel, available to Super Admins and Admins, and choose a month to see everyone's pay. Choose View on an employee to:

  • Set their basic salary and OT pay rate.
  • Add allowances and deductions, each for every month from now on or for this month only.
  • Print the salary slip.
  • Finalize the slip, which locks its amounts so later pay changes do not affect it. A finalized slip can be reopened.
Basic salary+Allowances+Overtime=Gross pay
Gross pay−Deductions=Net salary

The slip is A5 width and is A5 height when everything fits. With more lines, the page grows taller so that every allowance and deduction is listed. To keep this size, choose Save as PDF or a printer that accepts custom paper sizes, and set scale to 100%. A printer loaded with fixed A5 paper may continue a long slip onto a second sheet.

Basic salary is not reduced automatically for absence or for joining mid-month. Add a deduction when one is needed.

Reports

Reports and Excel export

On Attendance Reports, use Excel, CSV, JSON or Print / PDF to export the report on screen. To get everything at once, choose Export All Reports:

  1. Choose a date rangeToday, yesterday, this or last week, this or last month, or custom dates.
  2. Narrow it down, if you likeSelected people, an employee type, a department or a shift.
  3. Choose the reportsAll are ticked by default, and pay reports appear only for people allowed to see pay.
  4. Choose Build & Download

The Excel workbook has an Overview sheet showing the filters used, then one sheet per report. Clock-in and clock-out each have their own date and time columns, which matters when a shift runs past midnight. Dates and durations are real Excel values, so they can be sorted, filtered and added up. You can also download the reports as a ZIP of CSV files or as JSON.

Safety

Backup and restore

Go to Backup & Restore in the admin panel, available to Super Admins.

Create & Download Backup

Saves a copy in the backups folder and downloads it.

Export Data

Employees and attendance as CSV or JSON, and the system configuration as JSON.

Restore

Replaces all current data from a backup. The file is checked first, and a safety copy of the current data is saved beforehand.

Your data is in database/timora.db. Git ignores this file and the backups folder, so pushing to GitHub does not back up your data. Keep copies of your backups on another drive.

Safety

Critical Operations

This page is only available to Super Admins, and the permission cannot be given to any other role.

OptionWhat it does
Purge SelectedDeletes the rows you tick in the chosen table
Purge All ShownDeletes every row in the chosen table that matches the date and employee filters. With no filters, this is the whole table
Clean Up All DataDeletes all employees, attendance, overtime, salary data, leave, holidays and the audit log. Keeps shifts, settings and administrators
Reset EverythingReturns Timora to a new installation: default shifts and settings, the starter employee, and the login admin / admin@123

Safeguards: each operation shows what will be removed, requires your password and a typed confirmation word, and saves a backup first as timora-pre-purge-*.db or timora-pre-reset-*.db. Backup files are never deleted. To undo an operation, restore that file under Backup & Restore.

  • What else is removed: purging an employee also deletes all of their records. Purging a shift also deletes its assignments, and attendance records lose their link to that shift. If no shift remains, the starter shifts are added again.
  • Employee IDs: purges and cleanups do not reuse IDs, so numbering continues. Only Reset Everything restarts from EM001, with Heyshan Senaviratne.
Help

Troubleshooting

start-timora.bat and run.py explain most problems on screen. Common ones:

ProblemWhat to do
Python could not be installedCheck your internet connection, then install Python from python.org with Add python.exe to PATH ticked, and run the launcher again
Components could not be installedCheck your internet connection. On a company network, ask IT to allow pypi.org and files.pythonhosted.org. Details are in logs/install.log
Some files are missingExtract the whole ZIP first, then run the launcher from the extracted folder
Another program is using port 5000Close that program, or change port in config/settings.json to another number such as 5050
Timora is already runningThe launcher opens the browser on the running copy. To restart, close the first window, then run the launcher again
Not allowed to write to the folderMove the Timora folder to your Desktop or Documents
The clock shows the wrong timeSet Business Timezone in System Settings
An employee shows NOT SCHEDULEDCheck that they have a shift assigned and that today is one of its working days, then check for holidays, leave and whether the shift is active
An employee is missing from the dropdownInactive employees are not listed. Reactivate them under Employees
Too many failed loginsThe account locks for 15 minutes by default. Wait, or reset the password as shown under Default login
The connection-lost banner appearsThe server is unreachable, and nothing is recorded until it returns. Check that the Timora window is still open and the network is working

If startup still fails, the details may be in logs/timora-error.log.

API

All communication is JSON. Clocking in:

POST /api/attendance/clock
Content-Type: application/json

{ "employee_id": "EM001", "action": "clock_in", "request_id": "unique-id-per-attempt" }

Response:

{
  "success": true,
  "employee_id": "EM001",
  "employee_name": "Heyshan Senaviratne",
  "action": "clock_in",
  "timestamp": "2026-10-31T09:00:00Z",
  "local_time": "09:00:00 AM",
  "status": "clocked_in",
  "attendance_status": "Present",
  "note": "On time",
  "message": "Clock-in successful"
}

Errors use the same format:

{ "success": false, "code": "DUPLICATE_CLOCK_IN", "message": "Heyshan Senaviratne is already clocked in." }

Resending the same request_id returns the original result instead of recording a second event.

Safety

Security notes

Timora is built for a trusted local network.

Included: hashed passwords, a forced change of the default password, login lockout, session timeout, server-side permission checks, parameterized SQL, protection against cross-site requests, and a permanent audit trail.

  • The attendance screen has no login, by design. Anyone who can open it can see employee names and IDs, and can clock in or out as any employee.
  • Traffic is not encrypted. Timora uses plain HTTP, so do not expose it to the internet. For access beyond a trusted network, put it behind an HTTPS reverse proxy or a VPN.
  • Keep private files private. database/, backups/ and database/secret.key hold your data and session key. Git already ignores them; do not share them.
